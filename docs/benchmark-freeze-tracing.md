# 벤치마크 프리징 수집

`BENCHMARK_DEATH_DIAGNOSTICS`로 빌드한 진단 APK는 ADB 연결 없이 기존 엔진 비교 벤치마크에서 사망 구간을 기록한다. 완료 후 결과를 복사하면 `Death diagnostics`에 사망·런 종료·게임오버 화면의 구간 시간과 긴 프레임 사이의 GC·파이프라인 생성 수 변화가 포함된다. 일반 플레이에는 이 계측을 설치하지 않는다.

구간 시간은 중첩된 작업을 포함하므로 서로 더하지 않는다. 비동기 구간에는 정상적인 애니메이션 대기도 포함된다. 훅 설치가 첫 JIT 시점을 바꿀 수 있어 이 진단 실행은 엔진 순위를 판단하는 데 사용하지 않는다. GC 횟수나 파이프라인 생성 수 변화만으로 정지 시간을 확정할 수 없다. 자세한 스레드 상태가 필요하면 아래 시스템 추적을 함께 사용한다.

진단 APK를 `adb install -r <APK 경로>`로 설치한 뒤 런처의 기존 벤치마크 창을 열어 둔다. 게임 파일·계정·세이브를 지우지 않는다. 다른 앱의 시스템 추적은 종료해 둔다.

연결된 휴대폰이 하나일 때 저장소 루트에서 실행한다.

```bash
bash scripts/capture-benchmark-freeze.sh
```

스크립트에 `Recording`이 나오면 벤치마크 **시작**을 누르고 휴대폰을 그대로 둔다. 자동 재시작을 포함해 기록하며, 종료 시 출력되는 폴더에 추적 파일과 설정·기기 정보가 저장된다. 벤치마크 전체가 끝날 때까지 기록할 필요는 없다. 첫 전투 진입과 뒤이은 멈칫함을 담으면 된다. 녹화가 끝나도 벤치마크는 계속 진행하므로 앱의 취소 버튼으로 종료할 수 있다.

여러 기기가 연결됐거나 더 긴 기록이 필요하면 다음 인자를 사용한다. `--out`은 아직 존재하지 않는 폴더를 지정한다.

```bash
bash scripts/capture-benchmark-freeze.sh --serial <ADB 기기명> --seconds 300 --out /tmp/sts2-freeze-capture
```

Android 10 이상이 필요하다. 스크립트는 앱 설치·강제 종료·설정 변경·로그 삭제를 하지 않는다. ADB가 끊기거나 기록이 실패하면 오류로 종료하며, 로컬 진단 파일을 남긴다. 파일 크기 제한에 도달하면 요청한 시간보다 일찍 기록이 끝날 수 있다.

## 원인을 구분하는 순서

`benchmark.perfetto-trace`를 [Perfetto UI](https://ui.perfetto.dev)에 열고 앱 프로세스에서 `STS2Bench`를 검색한다. 자동 재시작마다 PID가 달라질 수 있다.

1. `ProcessFrameIntervalUs`가 크게 증가한 시점을 찾는다. 값은 **직전 프레임 신호부터의 시간**이므로, 증가 지점 앞쪽 구간을 확대한다. 화면에 실제로 표시된 프레임 시간이나 GPU 실행 시간 자체는 아니다.
2. 그 구간을 전투 화면 생성·첫 턴 준비·손패 대기·워밍업 표시와 비교한다. 비동기 작업 표시에는 정상적인 대기도 포함된다. 긴 표시만으로 CPU 병목이라고 판단하지 않는다. `.Entry`는 해당 메서드가 첫 Task를 반환할 때까지의 동기 구간이다.
3. `Capture.ReadbackAndPng`나 `SaveResults`와 겹치면 벤치마크의 GPU 이미지 읽기·파일 저장 비용부터 확인한다. 실 게임에서 본 프리징과 같은 원인인지는 별도로 확인한다.
4. 앱의 메인·렌더·로더 스레드에서 CPU 실행, 실행을 기다리는 상태, 잠든 상태를 비교한다. 파이프라인 생성 수와 GC 횟수 변화는 후보를 좁히는 단서로만 사용한다. GC 횟수는 정지 시간 측정값이 아니며 `dalvik` 추적만으로 게임의 Mono GC를 측정했다고 볼 수 없다.
5. 범위가 좁혀지면 해당 구간의 스택이나 더 세부적인 표시를 수집하고, 원인 후보 하나만 바꿔 같은 벤치마크에서 재검증한다.

일반 빌드의 시스템 추적 훅은 외부 Android 추적이 활성화된 상태로 벤치마크 단계에 들어갈 때 설치되고, 단계 종료 시 제거된다. 첫 추적의 `TraceSetup`은 진단 훅 설치 비용이므로 게임 로딩 비용과 구분한다. 원래 게임 Task와 예외 전달은 유지한다.

시스템 추적과 좁은 작업 구간 표시를 준비한 것으로, 전체 C# 호출 스택이나 정확한 Mono GC 정지 시간을 수집하는 구성은 아니다. 추적 자체도 약간의 비용을 더하므로 원인 후보를 확인한 뒤 추적을 끈 실행과 비교한다. GPU 단계와 FrameTimeline은 기기·드라이버·게임 출력 경로에 따라 제공되지 않을 수 있다. 트랙이 없다고 GPU 비용이 없다는 뜻은 아니다.
